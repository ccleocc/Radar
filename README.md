# 中国上市公司东南亚投资建厂公告雷达 V2.3.2

本项目是独立重建版，与旧版印尼招标新闻采集器的数据源逻辑分离。当前支持沪市、深市、北交所、新三板和港股的巨潮公告检索入口，由用户在采集页选择需要检索的市场。

## V2.3 分析逻辑重点

- 先确认公告中出现的东南亚国家/地区是否与投资、设立、生产制造或建设动作在相近原文段落内相关联；再进行机会评级。
- 不允许用 200 页融资/募集说明书中的境内厂房、境内募投项目或普通“建设”词命中，推断成东南亚工程机会。
- “明确新建/购买土地和厂房/生产基地/EPC/施工”等地域相关实体工程信号，一般列为高机会；“生产型子公司 + 明确产品生产/制造业务”也列为高工程跟踪价值，但必须提示厂房新建、租赁、改造及设备范围待核实。
- 只有东南亚投资、设立、考察、早期意向而没有实体建设/生产制造证据的，按观察或中等线索处理，不再因公告里别处出现大量国内建设词就升为高。
- 若未找到与东南亚项目相关联的证据，建设确定性显示“不适用”、工程机会显示“— 不纳入”，不作为项目商机入库。
- “公告复核”新增按当前规则重分析缓存公告的操作，用于清理旧版规则留下的误报。操作前请备份 `data/radar.db`。

## 核心目标

从上市公司公告及 PDF 正文中发现中国企业在东南亚的：
- 明确新建工厂、生产基地、制造基地、工业园、厂房和配套设施项目；
- 扩建、产能提升、生产线与生产设施建设项目；
- 尚处于拟投资、意向、选址、可研、规划、备案和前期筹备阶段的早期线索。

采用宽口径收录，随后分开标注“建设确定性”和“工程机会等级”。纯销售、纯贸易或未显示实体建设信号的单纯股权/金融事项会被排除或留在复核流程。

## 快速启动（Windows）

1. 安装 Python 3.10 或更高版本，安装时勾选 `Add Python to PATH`。
2. 完整解压 ZIP，不要单独复制 `app.py`。
3. 双击 `启动系统.bat`。
4. 首次启动会创建 `.venv` 并安装依赖，需要电脑能够访问 Python 软件包源。
5. 浏览器打开终端中显示的本地地址，通常为 `http://localhost:8501`。

也可手工启动：

```bash
python -m venv .venv
# Windows CMD
.venv\Scripts\activate
# macOS/Linux: source .venv/bin/activate
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

## 首次验证建议

1. 进入“公告复核”。
2. 点击“载入内置回归案例：志邦家居泰国智能制造基地”。
3. 进入“项目商机库”，确认生成项目档案。
4. 该案例预期识别：股票代码 603801、志邦家居；项目档案名称显示原始公告标题（示例标题为“关于向全资子公司、孙公司增资并对外投资项目的公告”），正文识别出泰国罗勇府、投资金额 20,000.00 万元人民币（或等值外币）、预计开工 2026-12-15、建设周期 18 个月、工程机会 ★★★ 高。由于公告披露前置审批尚待完成，建设确定性标注为“中”，并附带依据。
5. 再进入“公告采集”，先选择最近 30 天、一个或两个市场及较少翻页数，直接点击“开始采集”。如需先检查网络连接，请到“系统诊断”页面使用接口健康检查。

## 页面功能

- **总览**：项目档案、公告档案、机会等级和最近采集运行情况。
- **公告采集**：设置披露日期范围，并可选择沪市、深市、北交所、新三板、港股；关键词以紧凑标签显示，支持全选、全不选、反选、恢复默认、单个启停、删除和新增；词表及启用状态会持久保存。实时显示当前市场、关键词、页码、剩余组合、公告解析进度和临时/已保存结果。
- **后台采集与中断**：采集在后台线程运行，切换本应用页面不影响任务；最终入库前可以中断，中断后本轮临时公告与商机不写入正式数据表。最终入库阶段不再接受中断，以免人为造成部分保存。
- **项目商机库**：按公司、公告标题、国家、建设确定性和工程机会等级过滤；点击表格行可联动下方详情，并可删除单个商机档案（原始公告保留）。公告发布日列在第一位；不再将公告数量或公告时间线作为主要档案逻辑。
- **金额识别**：优先识别项目总投资，将上市公司出资单独列出；保留金额原文依据和其他金额候选项。显式美元金额不会再被当作人民币；表格中的单位说明也会尽量从附近字段标签中读取。
- **公告复核**：导入公告 PDF；查看已识别和未匹配公告；检查命中信号与原文依据；支持对已缓存正文进行规则重分析，并清理不再符合东南亚商机条件的旧档案。
- **数据导出**：项目和公告数据 CSV / Excel 导出。
- **系统诊断**：接口健康测试、每轮采集统计和错误明细。
- **V2.2.1 修复**：侧边栏进度摘要不再使用 `st.fragment` 渲染，规避 Streamlit 启动时的 `StreamlitAPIException`；主采集页的实时进度仍由独立片段刷新。启动脚本启用 Python UTF-8 模式，巨潮 JSON 优先按 UTF-8 解码，必要时回退到 GB18030。

## 关键词设置与检索边界

- 默认全文检索关键词共22项：投资、募集、购置、基地、产能、设立、工厂、厂房、印尼、泰国、印度尼西亚、越南、马来西亚、菲律宾、新加坡、缅甸、柬埔寨、老挝、文莱、东南亚、海外、东盟。
- “公告采集”页可点击每个关键词方块启用/停用，点击方块旁的“×”永久删除，或添加自定义词；关键词清单和启用状态保存到 `data/search_keywords.json`。点击“开始采集”时，本轮选择也会自动保存。
- 代码请求巨潮 `tabName=fulltext` 接口并通过 `searchkey` 传入关键词，设计意图是全文检索，而非仅搜索标题；命中后下载 PDF 并分析正文。具体覆盖率仍取决于巨潮网站当前的全文索引、接口行为和页数上限。
- 项目档案显示名改为原始公告标题，暂不再通过正则表达式猜测项目名称。来自巨潮的公告标题直接使用接口返回的正式标题；本地导入 PDF 时则使用文档标题识别结果/文件名作为标题。

## 自动定时采集

可以使用 Windows“任务计划程序”每天定时运行：

```cmd
项目目录\.venv\Scripts\python.exe 项目目录\run_daily.py --days 7 --pages 1 --max-pdfs 120
```

更精确的日期范围示例：

```cmd
项目目录\.venv\Scripts\python.exe 项目目录\run_daily.py --start-date 2026-10-01 --end-date 2026-10-10 --markets sse szse bj third hke --pages 2 --max-pdfs 200
```

脚本默认读取界面保存的全文检索关键词；也可用 `--regions` 或 `--keywords` 临时覆盖，例如：

```cmd
项目目录\.venv\Scripts\python.exe 项目目录\run_daily.py --days 30 --regions 泰国 越南 印尼 印度尼西亚 --pages 2
```

## 数据和维护

- 数据库在首次启动后自动创建：`data/radar.db`。
- 规则集中在 `radar/config.py`，可扩展国家别名、城市/省份、投资、建设、阶段和排除关键词。
- 采集记录按公告 ID 去重；项目档案显示名直接采用公告标题；按股票代码、国家/地区和公告标题生成档案键。金额候选项保存在档案中，供人工复核。
- 如果项目后续公告的正式项目名称差异很大，当前规则可能形成两个档案；这是 V2.0 后续可以通过人工合并/实体匹配增强的点。

## 重要限制

- 当前容器环境未安装 Streamlit，且联网 DNS 不可用，因此无法在本交付环境中实际打开 Streamlit 页面或执行真实 CNINFO 实时请求。V2.3 已完成 Python 编译检查和 30 项自动化测试，其中加入了针对侧边栏片段结构和中文 UTF-8 解码的回归测试；但这不等同于真实浏览器 UI 实机验收。真实网络可访问性应在你的电脑上通过“系统诊断”页面的接口健康检查验证。
- CNINFO 公开检索接口可能因网站变更、网络策略或反爬机制变化。程序采用 POST 表单、`YYYY-MM-DD~YYYY-MM-DD` 日期格式，并带浏览器常见请求头；若接口不可用，系统会记录具体异常，不会把抓取失败静默当作“无商机”。
- 扫描版 PDF 暂不自动 OCR；项目判断需营销人员结合原文复核。


## V2.3 分析规则回归样例

- **安井食品（2026-09-10）**：拟设立印度尼西亚生产子公司，披露速冻食品生产业务和冷链基础设施，并存在境外投资备案、企业设立和建设运营许可待办。新规则预期：收录为候选；工程机会高（制造运营/冷链工程潜力明确，实际厂房路径待核实）；建设确定性中。
- **泰晶科技（2026-10-09）**：公告明确在越南建设生产基地，资金用于购买土地和厂房、厂房建设与设备采购，但仍需办理境内外备案/许可。新规则预期：工程机会高；建设确定性中。
- **福达股份（2026-10-10）**：该可转债募集说明书中的制造建设项目位于浙江省嘉兴市的既有土地，没有找到东南亚项目所在地证据。新规则预期：不纳入东南亚工程商机；建设确定性“不适用”；金额和建设属性不从境内募投项目抽取。

以上三例均已加入自动化回归测试。金额单位、持股比例中的百分比、上市公司自有资金出资额与总投资承诺会分开识别。


## V2.3.2：Streamlit Cloud 部署与 HTML 清洗

- 新增 `DEPLOY_STREAMLIT.md`，说明 GitHub 仓库根目录布局及 Streamlit Community Cloud 部署步骤。
- `app.py` 会检查 `radar/analyzer.py` 是否存在；若模块文件漏传，会在页面给出可操作的目录提示。若项目目录被多套一层，也会尝试寻找完整的 `radar/` 包。
- 巨潮结果解析时统一清除公司名称和公告标题里的 `<em>` 高亮；数据库写入及读取阶段也会清洗历史数据中的 HTML 标签，覆盖公司名称、项目标题、地点、投资主体、合作方等可见属性。
- 公开部署可在 Streamlit Secrets 设置 `RADAR_ADMIN_PASSWORD`。密码配置后，未登录访问者只能浏览和导出；采集、关键词修改、PDF 导入、历史重分析及商机删除需要管理员登录。未配置密码时，为兼容本地开发，管理功能仍开放并显示提示。
- **部署注意：** 将 ZIP 解压后，把文件夹内的内容直接提交到 GitHub 仓库根目录；不要只提交 `app.py`，也不要把整个项目文件夹再套一层。部署主文件填 `app.py`，依赖由根目录 `requirements.txt` 提供。长期公开使用建议把 SQLite 切换为外部托管数据库；Streamlit Cloud 本地文件系统不应被当作永久存储。详见 `DEPLOY_STREAMLIT.md`。
